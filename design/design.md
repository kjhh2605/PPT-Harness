# Gnar design.md

> 슬라이드 스타일의 단일 진실 원천. 모델은 이 문서만 읽고 슬라이드를 만든다.
> 토큰 값의 기계용 사본은 `design/tokens.css`, 원천 데이터는 `design/palettes/brand.json`.

## 1. 색 (확정 · 2026-10-28)

**팔레트**: Deep Indigo Ink. 색상각 H 283, hero 채도 0.14. 바랜(faded) 톤이 브랜드 정체성이며, 강조는 선명함이 아니라 **단계 간 명도·채도 차이**로 만든다.

### 1.1 토큰

| 토큰 | Light | Dark | 역할 |
|---|---|---|---|
| `--bg` | #EDE9E6 | #181513 | 배경 |
| `--surface` | #F7F3EF | #24211F | 카드·패널 |
| `--text` | #262321 | #E8E4E1 | 본문 |
| `--muted` | #666260 | #A19E9B | 보조 글자·캡션 |
| `--border` | #D1CDCA | #383532 | 선·격자·비포커스 막대 |
| `--ink` | #37356A | #CACCFE | 제목·강조 문장 |
| `--hero` | #5A54AF | #9391F2 | 강조 한 곳(핵심 숫자·포커스 막대·구분선) |
| `--support` | #8183A4 | #707191 | 보조 막대·아이콘 |
| `--tint` | #DEDFF5 | #28293F | 콜아웃·표 머리 배경 띠 |
| `--brown` | #826144 | #B49072 | 따뜻한 중립 1 |
| `--taupe` | #736756 | #A39684 | 따뜻한 중립 2 |

차트 범주 순서(고정): `hero → support → brown → taupe → border`. 6번째 범주부터는 "기타"로 묶는다.

### 1.2 사용 규칙

1. **한 장에 hero는 한 요소.** 핵심 숫자 하나, 포커스 막대 하나, 또는 제목 밑 구분선 하나. 두 곳 이상이면 강조가 사라진다.
2. **차트는 포커스만 색.** 포커스 계열은 hero, 나머지는 border(회색). 범주가 정말 여러 개일 때만 1.1의 순서대로 쓴다.
3. **글자색 허용 범위.** text·ink는 어디든. hero는 큰 숫자·제목급(28px 이상)에서만. support·tint·border는 글자에 쓰지 않는다.
4. **tint는 면 전용.** 콜아웃 배경, 표 머리 띠. 그 위 글자는 ink.
5. **갈색·토프는 중립색.** 강조용이 아니라 hero와 회색 사이를 잇는 따뜻한 중간층. 차트 3·4번 범주, 아이콘, 표 구분에 쓴다.
6. **금지.** 순색(채도 0.2 이상), 그라데이션, 토큰 밖의 색, 한 장에 유채색 3종 이상.

### 1.3 발표별 색상 교체

색상(H)만 바꾸고 명도·채도 단계는 그대로 둔다. `design/scripts/ladder.py`의 SETS에 hue를 넣어 다시 생성하면 같은 바랜 톤의 다른 색이 나온다. 무채 베이스와 갈색·토프는 바꾸지 않는다.

### 1.4 대비 (검증값, 배경 대비)

| 단계 | Light | Dark | 판정 |
|---|---|---|---|
| text | 12.94:1 | 14.38:1 | 본문 가능 |
| ink | 9.26:1 | 11.75:1 | 본문 가능 |
| hero | 5.24:1 | 6.55:1 | 큰 글자·숫자 가능 |
| support | 3.04:1 | 3.86:1 | 면·막대만 |

## 2. 타이포그래피

- 글꼴은 **Pretendard Variable** 한 종류. CDN(jsdelivr dynamic subset)에서 불러오고 오프라인에서는 시스템 한글 글꼴로 대체된다. PPTX로 내보낼 때는 정적 패밀리(`Pretendard`, `Pretendard SemiBold`, `Pretendard ExtraBold`)로 바꾸고 가변 굵기(650·750)는 가장 가까운 정적 굵기로 내린다.
- 크기(1920×1080 기준 px): 제목 64(레퍼런스 비율에 따라 48~88), 본문 24~28, 캡션 20. **20px 미만 글자는 금지**하며 `render.mjs`가 검사한다.
- 글자색은 1.2절 3항을 따른다. 제목·강조 문장은 ink, 본문은 text, 보조 글자·캡션은 muted.

## 3. 그리드와 여백

- 캔버스는 1920×1080 고정. 브라우저 크기에 맞춰 비율을 유지하며 중앙에 축소하고, 인쇄는 16:9 한 장이다. 이 동작은 `scripts/slide_document.py`가 모든 슬라이드에 넣는다.
- 덱에서는 상단 헤더(브랜드 / 섹션 라벨)와 하단 각주(출처 / 쪽 번호)를 모든 장에 같은 위치로 둔다. 쪽 번호·상호 참조는 빌드가 채운다.
- 섹션 표지는 다크 토큰, 본문 장은 라이트 토큰이 기본이다.
- 캔버스 밖으로 나가는 요소, 잘린 텍스트, 글자 상자 겹침은 0건이어야 한다. 검사는 덱은 `render.mjs`, 레퍼런스는 `scripts/check-slides.mjs`.

## 4. 컴포넌트

- 텍스트·도형·차트·도식은 HTML/CSS/인라인 SVG로 만들어 편집할 수 있어야 한다. 차트는 PPTX 변환을 위해 인라인 SVG를 쓰고, 범주색 순서는 1.1절을 따른다.
- 한 장에 hero는 한 요소 또는 한 묶음(1.2절 1항). 콜아웃·표 머리는 tint 면 위에 ink 글자.
- 원본의 사진·입체 그래픽·장식은 같은 위치와 구도의 평면 도형이나 SVG로 단순화하고 변경 사실을 기록한다.
- 실제 화면 캡처는 그대로 쓰되 다크 프레임에 담는다. 제품 로고는 ink 단색 실루엣으로 바꾼다. 생성 이미지는 토큰 hex를 명시해 만들고 `decks/<deck-id>/assets/generated/`에 둔다.
- 레이아웃은 `reference/`의 화면을 가져와 내용만 바꾼다. 새 CSS와 새 레이아웃은 가까운 레퍼런스가 없을 때만 만든다.

## 5. 금지 규칙

- 순색(채도 0.2 이상), 그라데이션, 토큰 밖의 색, 한 장에 유채색 3종 이상(1.2절 6항).
- 원본 슬라이드 이미지를 배경으로 깔거나 SVG `image`로 넣어 끝내는 것.
- 20px 미만 글자, 캔버스 밖 요소, 잘린 텍스트.
- 청중용 화면에 제작 과정 흔적을 남기는 것: 발표자 메모, 제작용 근거 번호, 내부 쪽수 참조, 자료 변명. `audit-sources.mjs`와 `gnar-audience-reviewer`가 검사한다.
- 레퍼런스의 예시 숫자와 문구를 실제 현황 데이터처럼 쓰는 것. 새 주장·수치는 원본과 발표 대본에 있는 것만 넣는다.
