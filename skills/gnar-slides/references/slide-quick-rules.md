# Slide Quick Rules — 슬라이드 문장용 슬림 룰북 (v1.1)

전역 `humanize-korean` 플러그인의 `quick-rules.md`(v2.0, 산문용)를 **발표 슬라이드 문장**에 맞게 추린 프로젝트 전용 룰북이다. 전역 파일은 수정하지 않는다. 슬라이드는 산문과 달라서 문단 리듬·불릿 금지·장문 삽입 같은 규칙은 적용하지 않고, 짧은 구·명사형 종결·한 줄 길이 제약을 우선한다.

**사용 주체:** `.claude/agents/gnar-slide-humanizer.md`. 입력은 `extract-text.mjs`가 만든 `out/decks/<id>/slide-text.md`, 출력은 수정 제안 JSON(`humanize-edits.json`). 슬라이드를 직접 고치지 않는다.

## 0. 슬라이드 고유 제약 (산문 룰북에 없음 · 위반 시 제안 무효)

- **S-1 줄 수·길이 보존**: 한 항목(제목·부제·불릿·캡션)의 글자 수는 원문의 **±15% 이내**, 줄 수(`<br>` 분리)는 동일. 레이아웃이 깨지면 안 된다. 제안이 더 길어지면 제안하지 않는다.
- **S-2 종결 형태 통일**: 같은 묶음(한 장의 불릿들, 같은 열의 카드 제목들)은 종결을 하나로 맞춘다. 명사형(`~ 구성`, `~ 제공`)이면 전부 명사형, 서술형(`~합니다`)이면 전부 서술형. 묶음 안에서 섞인 것만 지적한다.
- **S-3 제목은 손대지 않는다**: 장 제목(`h1`)과 섹션 표지 문구는 발표자의 메시지라 보존. 부제·불릿·캡션·콜아웃·도식 안 문구만 대상이다.
- **S-4 보존 목록 (Do-NOT)**: 고유명사·제품명·모델명(Codex·Claude Code·Dots·피클·Aside·Orca·Paseo·Herdr 등), 수치·날짜·단위·퍼센트, 영어 약어(LLM·MCP·API·CLI·ADE·PR), 코드·명령·파일명(`$tutoring`, `/compact`, `AGENTS.md`, `.system(…)`), 큰따옴표 안의 인용·요청 문구, 영어 인용문, 각주의 출처 표기(`출처:`·`화면:`·`영상:`·`아이콘:`·`로고:`·`도구:`·`더 알아보기:`).
- **S-5 의미·서법 불변**: 당위(`~해야 합니다`)를 단정으로, 유보(`~일 수 있습니다`)를 단정으로 바꾸지 않는다. 내용 명사(앵커)는 원형 그대로 남긴다. 확신이 없으면 제안하지 않는다.
- **S-6 register 유지**: 덱의 기본 문체는 S-9의 역할별 종결이다. 격식을 올리거나(`하였습니다`) 평어로 내리지 않는다. 발표자의 1인칭 의견(`저는 ~라고 생각합니다`)은 보존.
- **S-7 빼기 전용**: 새 비유·수사·상투구·감탄을 넣지 않는다. 군더더기를 덜어내는 방향만 허용.
- **S-9 역할별 종결**: 문구의 역할에 따라 종결을 고른다. 모든 문구를 한 형태로 맞추지 않는다.
  - 정보 전달(카드·표 셀·불릿 설명, 사실 나열 부제, 캡션): 명사형(`~ 연결`, `~ 표시`) 또는 개조식 `~함`·`~음`. 평서 `~다`(`어려웠다`, `크다`)로 끝내지 않는다.
  - 핵심 메시지(장 제목이 문장일 때, 결론 한 줄, hero 문구, 발표자의 판단·다짐): 구어체 `~습니다`·`~합니다`. 짧은 구 제목(`X에서 Y로`)은 그대로 둔다.
  - 한 카드 안에서 설명은 `~함`, 그 아래 교훈 한 줄은 `~습니다`처럼 역할이 다르면 섞어도 된다. 같은 역할의 묶음 안에서만 S-2로 통일한다.
  - 위반 지적은 `rule: "S-9"`로 적고, 제목은 S-3에 따라 제안하지 않되 평서 `~다` 문장 제목은 `group_consistency`에 알린다.
- **S-8 변경 상한**: 덱 전체 항목의 **25% 이하**만 제안한다. 그 이상이면 확신 높은 순으로 자른다.

## A. 번역투 — S1~S2

- **A-1** `~에 대해(서)`·`~에 대한` → 목적격·관형격 직결(`API에 대한 설명` → `API 설명`)
- **A-3** `~에 있어(서)` → `~에서`
- **A-5** `~와 관련하여/관련된` → `~에`, `~의`
- **A-6** `~을 통해`·`~에 기반하여` 남발 → `~로`, `~으로`(`스킬을 통해 호출` → `스킬로 호출`)
- **A-7** `~을 가지고 있다`, have/make+명사 직역 → 형용사·동사(`높은 성능을 가지고 있다` → `성능이 높다`)
- **A-8** 이중 피동 `~되어진다/~지게 된다` → 단일 피동·능동
- **A-9** `~에 의해` 피동 → 행위자 주어(`AI에 의해 생성된` → `AI가 만든`)
- **A-11** `~을 위해` 목적절 → `~려고`, `~도록`, `~용`
- **A-15** 추상 주어 + 만능 동사(`제공한다/보여준다/가져온다`) → 구체 주어·동사
- **A-18** 명사 앞 3어절 이상 좌향 수식 → 짧은 구로 분리(슬라이드에서는 `<br>` 줄바꿈 안에서 해결, 줄 수 유지)
- **A-19** 이중 조사 `~에서의/~으로의/~에의` → 풀어쓰기
- **A-21** `단순한 X를 넘어 Y` → `X만이 아니라 Y`

## B. 영어·용어 — S2

- **B-1** 한글 + 괄호 영어 병기 반복 → 덱에서 첫 등장만 병기, 이후 한글만(슬라이드 단위가 아니라 **덱 단위**로 센다)
- **B-2** 설명 없는 광고성 buzzword(seamless·robust·leverage·혁신적·획기적) → 한국어로 풀거나 삭제. 표준 technical term(prompt·token·API)은 원어 보존

## D. AI 관용구 — S1

- **D-1** 결산 lexicon `결론적으로/따라서/이를 통해/요약하면/정리하자면` → 슬라이드에서는 전부 삭제(화면 구조가 이미 결론 자리를 보여 준다)
- **D-2** 의의 과장 `시사하는 바가 크다/주목할 만하다/매우 중요하다/핵심적인 역할` → 삭제 또는 구체 결론
- **D-3** 열거 도입 `크게 세 가지로/다음과 같은/다음과 같이` → 삭제하고 바로 항목
- **D-5** 의인화 추상 주어(`기술이 묻는다`, `시대가 요구한다`) → 사람·도구 주어
- **D-6** 결말 공식 `~할 때입니다/~시점입니다` → 구체 단언, 덱당 1회 이하
- **D-7** 변환 공식 `X에서 Y로/X를 넘어 Y로` 반복 → 직접 단언, 덱당 1회 이하
- **D-8** 분열문 `중요한 것은 ~이다/핵심은 ~다/관건은 ~다` → 주어-서술 직결
- **D-9** `~로 이어진다/직결된다`·논리 결산 `결국` 2회+ → 구체 인과 또는 단문
- **D-12** `과제도 남아 있다/한계도 분명하다` 문패 → 삭제, 실제 과제를 바로 쓴다
- **D-14** 사전 은유(`잠식·청사진·적신호·신호탄·뿌리내리다`)·감각 술어 평가문 → 명제로 직역화

## F. 수식·중복 — S2

- **F-4** `-성/-적/-화` 명사화 누적 → 동사·형용사 어근(`효율성을 제고` → `효율을 높임`)
- **F-5** `~적 N` 추상 체인 3회+ → 명사+명사(`전략적 함의` → `전략 함의`)
- **F-7** 범용 정책동사(`확대·강화·개선·확보·마련·구축`) + 추상 목적어 밀집 → 구체 행위 동사
- **F-8 (슬라이드 전용)** 부제가 제목을 다른 말로 되풀이하거나, 콜아웃이 본문 불릿을 그대로 요약 → 중복 쪽을 지적(삭제 제안은 `fix: ""`로 표기)

## G. 완곡 — S2

- **G-1** 같은 추측 종결 `~로 보인다/판단된다` 반복 → 유보 강도 유지한 채 형태만 변주
- **G-2** 이중 완곡 `~할 가능성이 있을 수 있다` → 완곡 하나만

## H. 접속사 — S2

- **H-4** `즉` 남발 → 삭제 또는 `곧`, 덱당 2회 이하
- **H-5 (슬라이드 전용)** 불릿 문두 접속사(`또한·그리고·하지만·그러나·따라서`) → 삭제. 불릿은 병렬이라 접속사가 필요 없다

## I. 형식명사 — S2

- **I-1 (슬라이드 전용)** `~하는 것/~한다는 것/~하는 부분/~하는 측면` 형식명사 종결 → 명사형·직설(`반복 입력을 줄이는 것` → `반복 입력 줄이기`)
- **I-2** `주목할 점은/~라는 점에 있다` → `X는 ~다`
- **I-3** `~다는 것이다/~다는 뜻이다` → `~다`
- **I-7** 출처 없는 `~다는 분석이다/평가다` → 직접 서술(출처 날조 금지)

## J. 장식 — S2

- **J-2** 따옴표 강조 남발(인용이 아닌 강조용) → 평어. 단 사용자 요청문·문서 인용·영어 인용은 보존
- **J-4 (슬라이드 전용)** 같은 장에서 `·`(가운뎃점) 나열과 `,` 나열, `/`가 섞임 → 하나로 통일(이 덱은 `·` 우선)
- **J-5 (슬라이드 전용)** 화살표 표기 혼용(`→`, `->`, `⇒`) → `→`로 통일

## 적용하지 않는 전역 규칙 (슬라이드 장르 예외)

- C-2(불릿 블록 금지)·C-9(숫자 인덱싱)·C-10(콜론 부제 헤딩): 슬라이드는 불릿·번호·`X: Y` 제목이 정상이다.
- C-11(연결어미 뒤 쉼표): 슬라이드 문장은 짧아 발동 빈도가 낮다. 보이면 지적하되 S1이 아니라 S2로 본다.
- E-1·E-2(문장 길이·종결 다양화): 슬라이드는 오히려 **종결 통일**(S-2)이 맞다. 다양화 제안 금지.
- J-1(볼드 제거): hero·ink 강조는 디자인 요소다. 건드리지 않는다.
- J-3(대시 분해): 짧은 부가 설명 대시는 슬라이드에서 허용.

## 자체검증 (제안 전 점검)

1. 보존 목록(S-4)의 토큰이 before/after에서 한 글자도 다르지 않은가.
2. after의 글자 수가 before의 115%를 넘지 않고 줄 수가 같은가.
3. 서법·register(S-5·S-6)가 그대로인가.
4. 새로 넣은 비유·수사·접속사가 없는가(S-7).
5. 같은 묶음의 종결이 after에서 통일됐고, 역할별 종결(S-9)에 맞는가.
6. 제안 수가 전체 항목의 25% 이하인가(S-8).

한 항목이라도 어긋나면 그 제안을 버린다.
