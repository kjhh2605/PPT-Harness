# 동적 페이지와 합성 이미지

기본 HTTP 응답만으로 실제 화면이 모두 보이지 않거나, 이미지 한 장 안에 여러 화면이 들어 있을 때만 읽는다.

## 동적으로 로드되는 페이지

- 공개 HTML의 `og:image`는 대표 이미지일 수 있다. 대표 이미지 하나를 전체 작품으로 간주하지 않는다.
- 사용 가능한 브라우저/서비스 도구의 실제 문서를 읽고 페이지를 연다. 로드된 본문 이미지의 `currentSrc`/`src`, 원본 크기, DOM 순서를 기록한다. 로그인이나 캡차 때문에 접근이 막히면 보이는 자료까지만 명확히 구분한다.
- 브라우저에서 관찰한 실제 이미지 URL을 사용한다. 예측한 API 주소를 연속으로 추측하거나, 다운로드하지 못한 이미지를 비슷한 임의 디자인으로 대체하지 않는다.
- 필요한 이미지가 모두 확보됐으면 브라우저 상태·쿠키·계정 정보 같은 관계없는 데이터는 수집하지 않는다.
- 내려받은 이미지는 `out/sources/<collection-id>/`에만 둔다. HTML 재구성이 끝나면 저장소에 남길 이유가 없다.

## 노트폴리오에서 확인한 사례

`https://notefolio.net/bysu.ppt/325182`는 초기 HTML에 대표 이미지만 노출됐고, 본문 로드 후에는 소개 보드 2개와 실제 슬라이드 14개가 있었다. **이 개수는 그 작품의 사례일 뿐 다른 링크에 고정 적용하지 않는다.** 본문 이미지의 파일명과 화면 비율, 직접 본 구성으로 원본 슬라이드를 구분했다.

## 이미지 하나에 여러 화면이 있을 때

- 각 화면의 경계와 읽기 순서를 먼저 정한다. 같은 화면의 확대·축소·기울어진 목업은 한 화면으로 센다.
- 기울어진 포트폴리오 목업만 있는 경우 정면 원본이 함께 있는지 우선 확인한다. 정면 원본이 없으면 복원 가능한 구조와 불확실한 부분을 기록한다.
- 긴 웹페이지는 의미 있는 구획별로 정리하되, 원래 PPT 장수인 것처럼 말하지 않는다. 자료의 형식과 사용자가 원하는 변환 범위가 충돌하면 확보한 화면 목록을 제시한 뒤 필요한 질문 하나만 한다.
- 원본이 이미 충분한 디자인 기준이다. 별도의 디자인 이미지를 생성해 원본 레퍼런스를 대체하지 않는다.

## 시각 확인 체크

제목·본문의 정확한 문구와 줄 수, 정렬 축, 화면 대비 여백, 컬럼 비율, 카드/표/차트의 수, 이미지 크롭, 도형 위치를 확인한다. 읽을 수 없는 문구나 출처가 불분명한 숫자를 만들어 넣지 않는다.
